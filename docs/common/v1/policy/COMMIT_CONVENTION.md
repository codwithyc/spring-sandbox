## COMMIT CONVENTION

해당 프로젝트는 커밋 메세지는 변경 의도를 한 눈에 파악할 수 있도록 Gitmoji 기반으로 작성합니다.

현재는 1인 프로젝트이므로 복잡한 규칙보다는 **일관성**을 우선으로 진행하며,
추후 Jira 연동이 완료되면 Jira 티켓 키를 포함하는 방식으로 확장할 수 있다.

### 커밋 템플릿
커밋 메시지 작성을 위해 프로젝트 루트의 `.gitmessage.txt` 파일을 사용한다.

적용 명령어:
`git config --local commit.template .gitmessage.txt`

### 커밋 메시지 형식
```text
<gitmoji> 제목

✨ 로그인 API 추가
🐛 게시글 수정 시 null 예외 처리
♻️ 공통 응답 구조 리팩토링
📝 브랜치 전략 문서 정리
✅ GlobalExceptionHandler 테스트 추가
🔧 application-dev 설정 수정
```

### 기본 사용 Gitmoji 목록
| Gitmoji | 의미    | 사용 기준                 |
| ------- | ----- | --------------------- |
| ✨ :sparkles:     | 기능 추가 | 새로운 기능, API, 로직 추가    |
| 🐛 :bug:     | 버그 수정 | 오류, 예외, 잘못된 동작 수정     |
| ♻️ :recycle:     | 리팩토링  | 기능 변경 없이 구조 개선        |
| 📝 :memo:    | 문서 수정 | 문서, README, 정책 파일 수정  |
| ✅ :white_check_mark:    | 테스트   | 테스트 코드 추가 및 수정        |
| 🔧 :wrench:     | 설정 변경 | 설정값, 빌드, 의존성, 스크립트 수정 |

### 필요할 때만 사용하는 Gitmoji

| Gitmoji | 의미       | 사용 기준                       |
| ------- | -------- | --------------------------- |
| 🚚 :truck:  | 파일 이동    | 파일 또는 디렉토리 경로 이동            |
| 🔥 :fire:   | 삭제       | 미사용 코드, 파일, 설정 삭제           |
| ⚡️ :zap:    | 성능 개선    | 성능 최적화, 쿼리 개선               |
| 👷 :construction_worker:     | CI/CD 변경 | GitHub Actions, 배포 파이프라인 수정 |
| 💚 :green_heart: | 빌드 복구    | 깨진 빌드, 테스트, CI 복구           |
| 🚑️ :ambulance:    | 긴급 수정    | 운영 이슈 등 긴급 대응               |

### 작성 규칙

- Gitmoji는 커밋 의도에 맞게 하나만 사용한다.
- 제목은 짧고 명확하게 작성한다.
- 마침표는 사용하지 않는다.
- 하나의 커밋에는 하나의 목적만 담는다.
- 의미가 애매하면 기본 Gitmoji를 우선 사용한다.

### 작성 기준
- 기능 추가가 핵심이면 ✨ 
- 버그 수정이 핵심이면 🐛 
- 구조 개선이 핵심이면 ♻️ 
- 문서 수정이면 📝 
- 테스트 변경이면 ✅ 
- 설정 변경이면 🔧 
- 파일 이동은 🚚 
- 삭제는 🔥
