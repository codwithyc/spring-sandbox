# ISSUE_POLICY

## 1. 목적
이 문서는 GitHub Issue 를 언제, 어떤 종류로, 어떤 단위로 열고 닫는지 정의한다.
목표는 다음과 같다.

- 개념을 먼저 검증(Study)하고, 기능(Feature)은 그 위에 살을 붙이는 순서를 지킨다.
- 이슈 하나가 «학습 테스트 + 문서»라는 같은 형태로 닫히게 해서 이력이 일관되게 남게 한다.
- 열어 두고 잊는 이슈를 만들지 않는다.

## 2. 이슈 종류

| 종류 | 제목 접두어 | 라벨 | 언제 연다 |
|------|------|------|------|
| Study | `[Study]` | 📚 Study | 개념을 학습 테스트로 검증할 때 |
| Feature | `[Feature]` | ✨ Feature | 검증한 개념을 써서 기능을 만들 때 |
| Bug | `[Bug]` | 🐞 BugFix | 잘못된 동작을 발견했을 때 |
| Docs | `[Docs]` | 📃 Docs | 정책·문서를 새로 만들거나 고칠 때 |
| Task | `[TASK]` | ⚙ Setting | 설정·인프라·도구 작업 |
| CI/CD · Release | `[CI/CD]` · `[Release]` | 🌏 Deploy | 파이프라인·배포 |

각 종류는 `.github/ISSUE_TEMPLATE/` 의 템플릿으로 연다.

## 3. Study → Feature 흐름

```text
Study 이슈   개념 정리 → 학습 테스트 → 이론 문서
   │
   ▼  (선행 Study 이슈 · 이론 문서 링크)
Feature 이슈 검증한 개념으로 기능 구현
   │
   ▼  (설계 결정이 생기면)
ADR         ADR_POLICY.md 기준으로 기록
```

- Feature 이슈 본문에는 그 기능이 기대는 **선행 Study 이슈와 이론 문서**를 링크한다.
- 선행 Study 가 없는 개념이 기능에 필요해지면, Feature 를 잠시 두고 Study 이슈를 먼저 연다.

## 4. Study 이슈 운영

### 4.1 단위
- **마일스톤 = 학습 장** (`01. Spring Core`, `02. Spring Boot` …). 장 순서는 학습 노트(노션 «Java & Spring») 목차를 따른다.
- **이슈 = 장 안의 주제 하나** (예: `01. Spring Core — 왜 필요한가`, `01. Spring Core — 빈 생명주기`).
- 이슈 하나는 하루~며칠 안에 닫을 수 있는 크기로 쪼갠다. 마일스톤 진행률은 닫힌 이슈 개수로 계산된다.

### 4.2 제목
```text
[Study] <장 번호>. <장 이름> — <주제>
예) [Study] 01. Spring Core — 왜 필요한가: 결합도와 DI
```

### 4.3 본문 필수 항목
- 학습 목표 · 핵심 질문
- 실험 체크리스트 (실험 하나 = 학습 테스트 하나 이상)
- 위치 (학습 테스트 경로, 이론 문서 경로)
- 완료 조건

### 4.4 완료 조건
아래가 모두 충족되면 PR 로 이슈를 닫는다.

- 실험 체크리스트의 학습 테스트가 모두 통과한다.
- 이론 문서를 `docs/common/v1/theory/` 에 `THEORY_DOCUMENT_TEMPLATE.md` 형식으로 작성했다.
- 학습 노트의 «실습» 항목에 예상한 동작 · 실행 결과 · 원리를 기록했다.

### 4.5 기록
- 진행 중 확인한 화면(학습 노트, 테스트 결과)은 캡처해서 이슈 댓글이나 PR «스크린샷» 항목에 첨부한다.
- 학습 시간은 매일 **09:00 ~ 12:00** 이다. 그날 한 일과 다음에 이어 할 일은 이슈 댓글로 남긴다.

## 5. 마일스톤
- 장을 시작할 때 하나만 연다. 끝나기 전에 다음 장 마일스톤을 열지 않는다.
- 마감일은 **점검일**이다. 그날 만족 여부를 보고, 부족하면 연장하되 이유를 마일스톤 설명에 한 줄 남긴다.
- 하위 이슈가 모두 닫히면 마일스톤을 닫는다.

## 6. 동시에 열어 두는 이슈
- 같은 종류의 이슈는 **한 번에 하나**만 진행한다.
- 진행하지 않을 이슈는 미리 열어 두지 않는다. 필요해지는 시점에 연다.

## 7. 닫기 규칙
- 이슈는 PR 본문의 `closed #번호` 로 닫는 것을 기본으로 한다.
- 작업 없이 닫을 때(범위 변경·중단)는 이유를 댓글로 남기고 닫는다.

## 8. 변경 규칙
- 이슈 운영 방식 변경은 이 문서를 먼저 수정한다.
- 이슈 종류를 추가하면 템플릿과 라벨을 함께 추가한다.
